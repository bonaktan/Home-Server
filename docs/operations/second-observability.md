# Second-host observability preparation

`compose.observability.yaml` and the second-host Prometheus/Loki and shared Alloy configuration are **not deployed or approved for unattended use**. The Compose model contains only the five intended observability services. It uses separate persistent volumes for Prometheus, Loki and Alloy positions and binds the two backend ports to the supplied Tailscale address. cAdvisor and Alloy have no published ports. Node-exporter uses the host network to report host networking metrics and listens on host port 19100; the verified firewall must restrict that port to the enrolled observability bridge. Set `SECOND_OBSERVABILITY_GATEWAY` to that bridge's actual gateway after inspecting the chosen Docker network; the default Docker bridge is not assumed reachable. It does not add Grafana or manage Pi-hole, Skybridge, Nextcloud or other projects.

The image inputs must be reviewed immutable `linux/amd64` manifest digests, not tags or local image configuration IDs. No versions or measured resource caps have yet been enrolled. Compose interpolation alone does not validate digest syntax or grant authorization. Install the stack only through the second host's reviewed Ansible and lifecycle path after that validation is implemented; the current playbook is only an identity preflight.

Binding to the Tailscale address is not authorization: inspect and test the effective firewall and tailnet policy to permit the Atom's enrolled identity and reject unrelated/CI principals, including IPv6. Loki's backend API is deliberately available to the authorized main host under D-33, not advertised as query-only. Confirm the address, existing port ownership and cutover procedure. The owner permits clearing the old second-host observability stack, but Pi-hole and independent workloads remain outside that permission.

Alloy currently selects only `/var/log/home-server/audit/*.log`, with the audit retention label. Do not place unreviewed logs there. The bounded capture producer, approved ordinary runtime sources, supported Promtail position migration, service lifecycle, and collector health and gap detection are not implemented. Review and test every source before enabling collection. Verify the selected Loki and Alloy versions and their container users can write their persistent volumes and read approved sources; do not solve permission failures by broadening host access blindly.

The Loki configuration targets seven days for ordinary streams and 30 days for audit streams using persistent compactor storage. These settings do not prove retained history: establish capacity, actual ingestion and searchable duration under restart, query and compaction load. Exercise loss of the inter-host link, independent local collection, source privacy, duplicate/gap behavior and rejection of unauthorized clients. Preserve the Atom's Grafana state and verify its cross-host queries and existing alert destinations separately. Compose rendering is a syntax check, not a deployment or runtime acceptance test.
