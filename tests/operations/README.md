# Operations tests

Run `python3 -m unittest discover -s tests/operations -p 'test_*.py'` on Debian with Python 3. The package-reporting fixture additionally uses `apt-listchanges`, `dpkg-deb` and `setsid`; it skips if the Debian packaging tools are unavailable. It builds a disposable package in a temporary directory and never installs it. The terminal test uses a local pseudo-terminal. Set `HOME_SERVER_ALLOY_TEST_BIN` to a reviewed Alloy binary to enable the loopback-only collection/restart fixture; it needs permission to bind local sockets and takes at least 15 seconds. The Ansible scope test uses a disposable local inventory and skips without ansible-core. No test should use production keys, send real notifications or stop production services.

These tests currently cover the read-only host entry point, package filter and synthetic APT hook, advisory size-state transitions, and the second-host Compose model. Compose rendering requires the Docker Compose CLI and does not need a Docker daemon. They do not establish the full Debian upgrade/privacy gate, deployed log rotation, actual backup collection, persistent alerts, access control or any restore. Add isolated fixtures and versioned evidence for the remaining design gates before enabling operations.

The backup status classifier reads one JSON object on stdin: `budget_bytes`, `used_bytes`, `observed_at`, `now`, `max_age_seconds` and `last_known`. Times are integer Unix seconds. Unknown readings are `null`; `last_known` is `ok`, `warning`, `exceeded` or `unknown`. Its JSON output includes the current `state` and the `last_known` state to persist. The collector must safely persist and supply that latter value, report stale observations separately, and measure destination usage and filesystem/provider capacity. The default classifier does not persist observations. The `--persist r2` or `--persist second_server` mode uses a pre-existing root-owned, non-group/world-writable `/var/lib/home-server/backup-status` directory, computes the evaluation time locally, serializes updates and durably stores the last accepted observation and warning state. Its stdin excludes `now` and `last_known`; it must be supplied only by a trusted collector with the reviewed budget and freshness policy. Late, stale and conflicting same-time observations cannot clear a warning. This is not yet wired to measurements, services or alerting; it does not cap uploads, prune data or stop services.
